# Maison Goya: local demo and free hosting

## Run locally

Use Node.js 22 or newer:

```sh
npm ci
npm run setup:demo
npm run dev
```

Open http://localhost:3000 and http://localhost:3000/admin.

Local administrator: `admin@goya.demo` / `MaisonDemo2026!`.

Customers create their own demonstration accounts. Use fictitious names, email addresses and delivery details, and a unique demo password. There is no email verification or password-reset email service in this demo.

`setup:demo` creates private Web Push keys in the ignored `.env.local` file and enables local storage with `DEMO_LOCAL=true`. Never commit this file or set `DEMO_LOCAL` on hosting.

Local data lives in `.data/shop.json`; uploaded photos live in `.data/uploads/`. Both are ignored by Git and excluded from deployment bundles. They survive app restarts on this machine. Local storage supports one running server process; use Neon for a deployed application.

## Deploy on Netlify Free + Neon Free

1. Create a Neon project and copy its pooled PostgreSQL connection string.
2. Import this Git repository into Netlify. The included `netlify.toml` sets `npm run build`, `.next` and Node 22. Netlify's Next.js adapter handles the server routes automatically.
3. Set these variables in Netlify's environment settings for **both builds and functions**:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Neon pooled PostgreSQL URL, including its SSL parameters |
| `APP_URL` | Exact HTTPS Netlify address, without a trailing slash |
| `ADMIN_EMAIL` | Your chosen demo administrator email |
| `ADMIN_PASSWORD` | A unique strong administrator password, at least 12 characters |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | Public push key generated by `setup:demo` |
| `VAPID_PRIVATE_KEY` | Matching private push key; keep secret |
| `VAPID_SUBJECT` | A valid `mailto:` contact address |

4. **Do not set `DEMO_LOCAL` on Netlify.** Hosted production fails closed without database configuration. It has no default administrator credentials.
5. Deploy. The first backend request creates and seeds the `maison_demo_store` table. The connection must have permission to create this table. Local data is not automatically copied to Neon.
6. Open `/admin`, sign in using your configured credentials, and publish a test product with an uploaded image. Hosted images are stored in the site's Netlify Blobs store, not the function filesystem.
7. Test the complete customer journey on the deployed HTTPS address before sharing it.

A free `*.netlify.app` address is sufficient for HTTPS, installation and Web Push. A custom domain is optional and purchased separately. Free plans have usage limits; do not promise unlimited traffic or uptime. Netlify's current Free plan uses a hard monthly credit allowance and may pause sites once it is exhausted.

## Storage model

This focused demo uses one versioned JSONB shop aggregate in PostgreSQL. Every mutation uses an atomic `UPDATE ... WHERE revision = ...` and retries a conflict, so concurrent serverless checkouts cannot both consume the last item. Prices are recalculated on the server, order details are immutable snapshots, duplicate checkout references are idempotent, and cancellation restores stock exactly once.

This is intentionally a small demo architecture. A live merchant deployment should move to normalized tables, durable background jobs, approved payment integrations, production identity workflows, audit trails and database migrations. This project is not a live payment system.

## Notifications and installation

The manifest supplies app icons, standalone display and customer shop/orders shortcuts. A service worker supplies an offline reconnection page and Web Push handling. It never caches account pages or API responses. Availability and checkout require a network connection.

Customers enable notifications from their account. Notifications are stored in the account even if push is unsupported, denied or not configured. Order updates and announcements are sent to opted-in devices in the user's selected language. Signing out removes the current device subscription.

On supported iPhones/iPads, add the site to the Home Screen before enabling notifications. A physical-device installation and push delivery check is still required after deployment; a desktop manifest/service-worker check does not prove delivery on every device.

## Demo script

1. Owner signs in at `/admin` and opens Products.
2. Owner adds photos, English/French copy, prices and size quantities, then publishes.
3. Customer searches using either language, selects an available size and adds it to the bag.
4. Customer signs in or creates an account before entering `/app/shop`, then chooses a size and enters fictitious delivery details at checkout.
5. Customer chooses Mobile Money, enters a fictitious number, sends a demo request and approves or declines it. No actual wallet request, SMS, PIN or money transfer is involved.
6. A successful order is saved and stock decreases. A rejected payment leaves the bag intact.
7. Owner moves the order from Confirmed to Preparing to On its way to Delivered. Cancellation is available before shipping and returns stock.
8. Customer sees the updated journey in their account and, where enabled and supported, receives Web Push.
9. Owner publishes a bilingual new-arrival announcement. It appears in the collection and customer updates.

Updates refresh automatically while the page is visible, on window focus and immediately between tabs on the same browser. They are periodic updates, not a permanently open realtime socket.
